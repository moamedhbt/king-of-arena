# ملك الحلبة — MVP v0.1

لعبة ويب ثلاثية الأبعاد لـ 2 إلى 8 لاعبين في المتصفح: **لغز عقلي** يمنحك خيارًا أفضل، ثم **معركة دفع** على حلبة تنهار. بلا حسابات، بغرفة وكود من 4 حروف ورابط دعوة.

> الشعار: الذكاء يمنحك خيارًا أفضل، والمهارة تحسم المعركة.

---

## التشغيل السريع

```bash
npm install
npm run build      # يبني العميل (Vite) والخادم (esbuild)
npm start          # خدمة واحدة على http://localhost:3000
```

للتطوير مع إعادة التحميل:

```bash
npm run dev:server   # الخادم على :3000
npm run dev:client   # Vite على :5173 (يعيد توجيه /socket.io إلى :3000)
```

### اللعب مع الأصدقاء
1. افتح الموقع، أدخل اسمك، اضغط **أنشئ غرفة**.
2. اضغط **نسخ رابط الدعوة** وأرسله (`https://…/?room=ABCD`).
3. حين ينضم لاعبان على الأقل، صاحب الغرفة يختار **3/5/7 جولات** ويضغط **ابدأ**.

### التحكم

## البنية

```
/shared      الأنواع + config.json + مولّدات الألغاز وحلّالها + حساب النقاط والهندسة
/server      Node 20 + Socket.io — محاكاة 30Hz، لقطات 20Hz، آلة حالات الغرفة، السجل
/client      Three.js + Vite + TS — العرض، الكاميرا، الواجهة العربية RTL، الصوت
/tests       الألغاز، المحاكاة، العدالة، الشبكة الشاملة (E2E)
/data        rounds.jsonl (سجل كل جولة)
/docs        لقطات الشاشة + وثائق التغييرات
```

الخادم يقدّم الملفات الثابتة و WebSocket من **خدمة واحدة** (PORT من متغيّر البيئة).

### أين تُعدَّل الأرقام؟
كل شيء في [`shared/config.json`](shared/config.json) — البنية والمحاكاة تقرأ منه، ولا رقم توازن مكتوب في الكود.

## العدالة (خادم الحكم الوحيد)

- الفيزياء والألغاز والتوقيت والنقاط كلها على الخادم. العميل يرسل **اتجاهًا مقصوصًا إلى طول 1** وأحداث ضغط فقط.
- كل العشوائية من **بذرة واحدة للمباراة** (mulberry32 + اشتقاق FNV): نفس المدخلات = نفس النتيجة.
- كل حدث مؤثر معلن مسبقًا: تحذير البلاطة **2.5 ث** قبل سقوطها، ومحتوى المنصات (لاحقًا) بدورة كاملة.
- بداية متساوية: دائرة نصف قطرها 6 وحدات، توزيع مواضع مبذور، سرعة وقوة موحّدتان.
- لا كرة ثلج: بونص اللغز **+2/+1** فقط وينتهي بانتهاء الجولة، وكل جولة تبدأ من الصفر.
- المتفرج لا يؤثر على الحلبة إطلاقًا (التوقع +1 نقطة فقط).
- لكل هزيمة سبب مفهوم في ملخص الجولة: «دفعة من فلان» أو «انهيار البلاطة».

## ما يعمل الآن (M1→M5)

- **M1** غرف بكود ورابط دعوة، لوبي، حركة متزامنة بأربعة لاعبين وأكثر.
- **M2** الحلبة 9×9، انهيار متوقع، تصادم واندفاع، سقوط، نقاط، شاشات نتائج، إعادة اللعب.
- **M3** الألغاز الأربعة بالتوقيت العادل (توقيت فعلي = استلام − إرسال − RTT/2) وترتيبها وبونصها.
- **M4** مرحلة الاختيار (اختيار واحد + مخزون حي) والأدوات الأربع بآثارها.
- **M5** مرئيات low-poly، صوت مُولَّد، تحكم جوال، اهتزاز، سجل JSONL، تنعيم وإسقاط لقطات.

آلة الحالات: `LOBBY → COUNTDOWN → PUZZLE → DRAFT → ARENA_INTRO → ARENA → ROUND_RESULT → (PUZZLE | MATCH_RESULT) → LOBBY`
وكل مرحلة تحمل `endsAt` بزمن الخادم المطلق، والعميل يزامن ساعته كل 10 ثوانٍ (ping كل 2 ث).

## النشر (Render / Railway / Fly.io)

الخدمة واحدة، فلا حاجة إلا لأمرين:

```bash
npm install && npm run build
npm start        # PORT يقرأ من البيئة (افتراضي 3000)
```

- **Render:** Web Service، Build: `npm install && npm run build`، Start: `npm start`، Health check: `/health`.
- **Railway:** نشر من المستودع، نفس الأوامر، أضف `PORT` تلقائيًا.
- **Fly.io:** `fly launch` مع `internal_port = 3000`، ثم `fly deploy`.
- HTTPS مطلوب (WebSocket يعمل فوقه)، والرابط نفسه يخدم اللعبة ورابط الدعوة.
- متغيّرات اختيارية: `DATA_DIR` (مسار سجل الجولات)، `TELEMETRY=off`، `CLIENT_DIR`.

> ملاحظة: الغرف في الذاكرة — خدمة واحدة فقط بلا تعدد نسخ، وهذا كافٍ لـMVP.
